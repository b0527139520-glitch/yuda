# הוספת סיפור לקטלוג של יהודה טאוב

## הדבר הכי חשוב: איזה ענף

**הענף שממנו GitHub Pages באמת מגיש את האתר הוא:**

```
claude/add-yosi-ben-yoezer-stories-w18153
```

**לא `main`!** זו לא טעות הקלדה — זה ריפו שבו מישהו הגדיר את GitHub Pages
להגיש מענף פיצ'ר ישן במקום מ-main, וזה לא מובן מעצמו משום מקום בממשק של
GitHub. דחיפה ל-main לא תופיע באתר אף פעם, גם אם ה-PR התמזג בהצלחה.

**לפני שמתחילים לעבוד, תמיד מוודאים איזה ענף Pages באמת מגיש**, כי ייתכן
שבעתיד מישהו ישנה את זה ב-Settings → Pages:

```bash
# בדיקה: אילו ריצות build הצליחו לאחרונה ומאיזה ענף
# (או פשוט לשאול את המשתמש: "איזה ענף רואים ב-Settings → Pages → Source?")
```

אם אין גישה לבדוק את הגדרות Pages ישירות — התאמה קלה: להשוות את התוכן החי
באתר (מה שהמשתמש רואה בדפדפן) לתוכן של `index.html` בענף `claude/add-yosi-
ben-yoezer-stories-w18153` ולא ב-main.

## המבנה

- **ריפו:** `b0527139520-glitch/yuda`
- **ענף חי:** `claude/add-yosi-ben-yoezer-stories-w18153`
- **קובץ:** `index.html` בשורש הריפו (מסמך HTML עצמאי ומלא, לא fragment)
- **כתובת האתר:** `https://b0527139520-glitch.github.io/yuda/`
- **קישור לסיפור בודד:** `https://b0527139520-glitch.github.io/yuda/#story-N`

זהו קובץ שנבנה בעבר עם וריאציה עשירה יותר מהתבנית הבסיסית של סקיל
`candy-pop-storybook` — יש בו שדות שאין בתבנית הרגילה:

| רכיב | איפה |
|---|---|
| `<span class="teacher-badge">` | תג "כולל מדריך למורה" בכותרת כל סיפור |
| `<div class="story-navigation">` | קישורי "→ הסיפור הקודם" / "הסיפור הבא ←" + "חזרה לתוכן העניינים" |
| `const searchData = [...]` | מערך JS נפרד (לא `book.js` הרגיל של הסקיל) — כל סיפור הוא `{id, title, body}` עם הטקסט המלא ללא תגיות HTML |
| בתוך `story-body` | תקציר (`<ul class="story-list">` עם 4 סעיפים), ואז `## הַסִּפּוּר הַמָּלֵא: ...` כפסקה, `<hr class="story-sep">`, כותרות `<h3 class="section-heading">🔹 א. ...` לכל קטע, חלק "💎 חִבּוּר עֶרְכִּי: ME - WE - YOU", חלק "👨‍🏫 מַדְרִיךְ לַמּוֹרֶה / לַמְּסַפֵּר" (שאלת פתיחה, הערות ביצוע, המלצות למצגת, פעילות מסכמת), וחלק "📚 מְקוֹרוֹת" |

**תמיד לשמור על אותו פורמט** כשמוסיפים סיפור חדש — לא לחזור לתבנית הפשוטה
של הסקיל הבסיסי.

## תהליך העבודה להוספת סיפור

1. **למשוך את הענף הנכון, לא main:**
   ```bash
   git fetch origin claude/add-yosi-ben-yoezer-stories-w18153
   git checkout -B claude/add-yosi-ben-yoezer-stories-w18153 origin/claude/add-yosi-ben-yoezer-stories-w18153
   ```

2. **לבדוק מהו מספר הסיפור הגבוה ביותר הקיים בפועל** (אל תניחו שזה 145 —
   ייתכן שנוספו עוד סיפורים בינתיים):
   ```bash
   grep -o 'id="story-[0-9]*"' index.html | sort -t- -k2 -n -u | tail -1
   ```
   הסיפור החדש מקבל את המספר הבא ברצף.

3. **לבחור צבע ואייקון לפרק** — צבעי הפלטה שכבר בשימוש (מחזור, לא נורא
   לחזור על צבע, רק להימנע מלחזור על הצבע של הפרק הקודם ממש):
   ```
   ירוק:   #00b894 / #006b56
   אדום:   #ff4757 / #8b0000
   צהוב:   #ffd93d / #e08e00
   כחול:   #4ec9f0 / #1a6fa0
   סגול:   #a29bfe / #6c5ce7
   ירוק בהיר: #7bed9f / #2e7d50
   ורוד:   #ff6b9d / #c62b6b
   ```
   אייקון תואם לתוכן הסיפור (לא לדמות עצמה בהכרח — למשל 🧺 לסל, 🐑 לצאן,
   ✉️ למכתב).

4. **לכתוב את גוף הסיפור** באותו מבנה של הסיפורים הקיימים (ראה טבלה
   למעלה) — תקציר 4 סעיפים, סיפור מלא עם כותרות `🔹 א/ב/ג...`, ME-WE-YOU,
   מדריך למורה, מקורות עם מראה מקום מדויק (מסכת ודף).

5. **להכניס בארבע נקודות בקובץ** (לפי סדר המסמך):
   - כניסת תוכן עניינים חדשה, ממש לפני `  </aside>`
   - עדכון ה-navigation של הסיפור שהיה אחרון (מוסיפים לו קישור "הסיפור
     הבא ←" לסיפור החדש)
   - `<section class="chapter-section">` + `<article class="story-card">`
     חדשים, ממש לפני `  </main>`
   - שורה חדשה במערך `searchData`, לפני ה-`];` הסוגר — **בלי לשכוח פסיק
     אחרי הרשומה הקודמת!** (זו הייתה תקלת ה-JS בפעם הקודמת)
   - עדכון מונה הסיפורים ב-hero (`📚 X סיפורים` ו-`👑 X גדולי ישראל`)

6. **לוודא** שאין תווים לא-בורחים (`'`) בתוך מחרוזות ה-JS של `searchData` —
   כל גרשיים בעברית (כמו "ה'") צריכים escape ל-`\'`.

7. **לאמת** עם הסקריפט של סקיל `candy-pop-storybook`:
   ```bash
   python3 /root/.claude/skills/synced/candy-pop-storybook/scripts/validate_book.py index.html
   ```
   לא לדחוף לפני שכל הבדיקות עוברות (הוא בודק גם ש-JS מתפרסר תקין).

8. **לדחוף ישירות לענף החי** (לא ל-main, לא PR — הענף הזה עצמו הוא המקור
   ל-Pages, אז דחיפה אליו = חי תוך דקה-שתיים):
   ```bash
   git add index.html
   git commit -m "..."
   git push origin claude/add-yosi-ben-yoezer-stories-w18153
   ```

9. **לוודא ש-build הצליח** (אופציונלי אך מומלץ) — Pages רץ כ-GitHub
   Action בשם `pages-build-deployment`; אפשר לבדוק שהריצה האחרונה על
   ה-SHA שדחפתם הסתיימה ב-`success`.

## דברים שכבר הפילו אותנו פעם אחת

- **דחיפה ל-main לא עושה כלום** לאתר החי. תמיד `claude/add-yosi-ben-yoezer-
  stories-w18153`.
- **שכחת פסיק** בין הרשומה האחרונה הקיימת ל-searchData לרשומה החדשה
  שוברת את כל ה-JS בשקט (הדף עדיין נטען, אבל שום סקריפט לא רץ — כולל
  חיפוש והעתקת קישור). ה-validator תופס את זה, אז תמיד להריץ אותו.
- **תיקיות/קבצים בעברית** ב-URL הופכים ל-percent-encoding מכוער — לכן
  `index.html` נשאר תמיד בשורש, לא בתיקיית משנה.
